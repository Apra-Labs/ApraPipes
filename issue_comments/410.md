## Analysis and Suggested Implementation

### Problem
H264NvCodec encoder becomes unstable in Docker:
- **Mp4Writer sink**: Only first output file is playable, subsequent files are corrupted
- **RTSP Pusher sink**: Stream playable once, then inaccessible

Works correctly on host system but fails in Docker after some time.

### Root Cause Analysis

**Key Observations:**
1. Works initially, then degrades (suggests resource leak or corruption)
2. Docker-specific (host system works fine)
3. Affects both Mp4Writer and RTSP Pusher (encoder issue, not sink issue)
4. Long-running sessions are more affected

**Likely Root Causes:**
1. **GPU resource management in Docker**: NVENC encoder resources not properly released
2. **Buffer management**: Encoded buffers accumulating or being reused incorrectly
3. **Docker GPU passthrough issues**: CUDA context or NVENC session becoming stale
4. **Memory leaks**: Gradual memory corruption affecting encoder state

### Potential Fixes

**Fix 1: Proper NVENC Resource Cleanup**

```cpp
// In H264EncoderNVCodecHelper.cpp
class Detail {
private:
    NV_ENCODE_API_FUNCTION_LIST nvEncApi;
    void* encoder = nullptr;
    
public:
    ~Detail() {
        // Ensure proper cleanup order
        if (encoder) {
            // Flush any pending frames
            flushEncoder();
            
            // Destroy all buffers BEFORE destroying encoder
            for (auto& buffer : outputBuffers) {
                nvEncApi.nvEncDestroyBitstreamBuffer(encoder, buffer);
            }
            for (auto& buffer : inputBuffers) {
                nvEncApi.nvEncDestroyInputBuffer(encoder, buffer);
            }
            
            // Destroy encoder session
            nvEncApi.nvEncDestroyEncoder(encoder);
            encoder = nullptr;
        }
        
        // Release CUDA context
        if (cuContext) {
            cuCtxDestroy(cuContext);
            cuContext = nullptr;
        }
    }
};
```

**Fix 2: Reset Encoder Between Files**

```cpp
// In H264EncoderNVCodec.cpp
bool H264EncoderNVCodec::handleCommand(Command cmd) {
    if (cmd.getType() == Command::FileClose) {
        // Reset encoder state between files
        resetEncoder();
    }
}

void H264EncoderNVCodec::resetEncoder() {
    // Flush encoder
    helper->flush();
    
    // Optionally recreate encoder for fresh state
    if (mProps.resetEncoderPerFile) {
        helper.reset();
        helper = std::make_unique<Detail>(mProps);
    }
}
```

**Fix 3: Buffer Pool Management**

```cpp
// In H264EncoderNVCodecHelper.cpp
class BufferPool {
private:
    std::vector<NV_ENC_OUTPUT_PTR> availableBuffers;
    std::vector<NV_ENC_OUTPUT_PTR> inUseBuffers;
    std::mutex poolMutex;
    
public:
    NV_ENC_OUTPUT_PTR acquireBuffer() {
        std::lock_guard<std::mutex> lock(poolMutex);
        
        if (availableBuffers.empty()) {
            // Create new buffer
            NV_ENC_CREATE_BITSTREAM_BUFFER createParams = {};
            NV_ENC_OUTPUT_PTR buffer;
            nvEncApi.nvEncCreateBitstreamBuffer(encoder, &createParams);
            return buffer;
        }
        
        auto buffer = availableBuffers.back();
        availableBuffers.pop_back();
        inUseBuffers.push_back(buffer);
        return buffer;
    }
    
    void releaseBuffer(NV_ENC_OUTPUT_PTR buffer) {
        std::lock_guard<std::mutex> lock(poolMutex);
        
        // Move from in-use to available
        auto it = std::find(inUseBuffers.begin(), inUseBuffers.end(), buffer);
        if (it != inUseBuffers.end()) {
            inUseBuffers.erase(it);
            availableBuffers.push_back(buffer);
        }
    }
};
```
