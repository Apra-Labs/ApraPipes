## Analysis and Suggested Implementation

### Problem
Frame and Module base classes allow instantiation without enforcing certain behaviors in derived classes. Making them abstract would enforce compile-time implementation requirements.

### Analysis: What Methods Should Be Pure Virtual?

**For Module class:**
```cpp
// In Module.h
class Module {
public:
    // These are likely candidates for pure virtual:
    virtual bool validateInputPins() = 0;  // Each module must validate its inputs
    virtual bool validateOutputPins() = 0; // Each module must validate its outputs
    
    // Maybe pure virtual (depends on design):
    virtual bool handleCommand(Command cmd) = 0;  // Module-specific command handling
    
    // Definitely NOT pure virtual:
    virtual bool init();  // Has default implementation
    virtual bool step();  // Has default implementation
};
```

**For Frame class:**
```cpp
// In Frame.h
class Frame {
public:
    // Candidates for pure virtual:
    virtual size_t getDataSize() const = 0;  // Each frame type must know its size
    virtual FrameType getFrameType() const = 0;  // Each frame must have a type
    
    // Maybe pure virtual:
    virtual Frame* clone() const = 0;  // Deep copy
    
    // NOT pure virtual:
    virtual void* getData();  // Has default implementation
};
```

**Step 2: Fix derived classes first**

Before making base classes abstract, ensure all derived classes implement required methods:
```cpp

class Mp4ReaderSource : public Module {
public:
    bool validateInputPins() override {
        // Implement validation
        return true;
    }
    
    bool validateOutputPins() override {
        // Implement validation  
        return outputPins.size() > 0;
    }

```

**Step 3: Make base classes abstract**

After all derived classes are updated:
```cpp
// In Module.h
class Module {
public:
    // Make key methods pure virtual
    virtual bool validateInputPins() = 0;
    virtual bool validateOutputPins() = 0;
    
protected:
    Module() = default;  // Prevent direct instantiation
};
```

### Recommended Approach (Conservative)

Start with a minimal set of pure virtual methods:

**For Module:**
```cpp
class Module {
public:
    // Only make methods pure virtual that:
    // 1. Have no sensible default implementation
    // 2. Are critical for module functionality
    // 3. Every derived class should override
    
    virtual ~Module() = default;
    virtual std::string getModuleType() const = 0;  // Every module needs a type
    
    // Keep these with default implementations:
    virtual bool init();
    virtual bool step();
    virtual bool handleCommand(Command cmd);
};
```

**For Frame:**
```cpp
class Frame {
public:
    virtual ~Frame() = default;
    virtual FrameType getFrameType() const = 0;  // Every frame needs a type
    virtual size_t getDataSize() const = 0;      // Every frame needs a size
    
    // Keep these with default implementations:
    virtual void* getData();
    virtual bool copyData(const void* src, size_t size);
};
```

### Migration Guide

Create a migration guide for external users:

**Before:**
```cpp
class MyModule : public Module {
    // Could leave methods unimplemented
};
```

**After:**
```cpp
class MyModule : public Module {
    // MUST implement these methods:
    std::string getModuleType() const override {
        return "MyModule";
    }
    
    // SHOULD implement these for proper functionality:
    bool init() override {
        return Module::init();  // Can call base implementation
    }
};
```

### Files to Examine:
- `base/include/Module.h` - Module base class
- `base/include/Frame.h` - Frame base class
- `base/src/Module.cpp` - Module implementation
- All derived class headers in `base/include/`

### Breaking Changes:
- External modules will need to implement pure virtual methods
- May break user code that derives from Module or Frame
- Requires version bump (major version change)

### Benefits:
- Compile-time enforcement of implementation requirements
- Prevents silent fallback to default behavior
- Makes design intent explicit
- Catches implementation errors early
