## Analysis and Suggested Implementation

### Problem
CMake configuration takes ~68x longer on Linux (68 minutes) than Windows (1 minute), despite using cached vcpkg dependencies.

### Analysis

**Key Observations:**
1. Both platforms use cached vcpkg (not building dependencies)
2. Same CMake version (3.29.6)
3. Massive performance difference suggests I/O or filesystem issue

**Likely Causes (in order of probability):**
1. **vcpkg toolchain file I/O**: Excessive filesystem scanning
2. **find_package() performance**: CMake scanning many directories
3. **Filesystem type**: Network-mounted or slow filesystem on Linux runner
4. **vcpkg manifest mode**: Re-evaluating dependencies on each configure

### Investigation Steps

#### 1. Enable CMake Profiling

**Add CMake profiling to workflow:**
```yaml
# In .github/workflows/build-test.yml
- name: Configure (with profiling)
  run: |
    cmake -B build -S base \
      --profiling-output=cmake-profile.json \
      --profiling-format=google-trace \
      -DCMAKE_VERBOSE_MAKEFILE=ON
```

**Analyze the profile:**
```bash
# View the profile in Chrome://tracing or analyze with jq
cat cmake-profile.json | jq '.traceEvents[] | select(.dur > 1000000) | {name, dur}'
```

#### 2. Diagnostic Commands

Add these to CI to gather data:

```yaml
- name: Diagnose CMake performance
  run: |
    # Check filesystem type
    df -T ${{ github.workspace }}
    
    # Time individual CMake operations
    time cmake -B build -S base --trace-expand > cmake-trace.log 2>&1
    
    # Count find_package calls
    grep "find_package" cmake-trace.log | wc -l
    
    # Find slowest operations
    grep -E "^\s+\[" cmake-trace.log | tail -1000
    
    # Check vcpkg installed packages
    vcpkg list
```

### Potential Fixes

**Fix 1: Use CMake file API instead of configure_file globbing**

If CMakeLists.txt uses `file(GLOB ...)`, replace with explicit file lists:
```cmake
# BAD (slow on some filesystems):
file(GLOB_RECURSE SOURCES "src/*.cpp")

# GOOD (faster):
set(SOURCES
    src/file1.cpp
    src/file2.cpp
    # ... explicit list
)
```

**Fix 2: Optimize vcpkg usage**

```cmake
# In CMakeLists.txt
# Set vcpkg to use binary caching more aggressively
set(VCPKG_INSTALL_OPTIONS "--no-print-usage")
set(CMAKE_FIND_PACKAGE_PREFER_CONFIG TRUE)
```

**Fix 3: Use ccache for CMake**

```yaml
# In workflow
- name: Cache CMake files
  uses: actions/cache@v3
  with:
    path: |
      build/CMakeCache.txt
      build/CMakeFiles
    key: cmake-${{ runner.os }}-${{ hashFiles('**/CMakeLists.txt') }}
```

**Fix 4: Reduce find_package calls**

```cmake
# In CMakeLists.txt
# Cache find_package results
if(NOT TARGET opencv::opencv)
    find_package(opencv CONFIG REQUIRED)
endif()
```

**Fix 5: Use tmpfs for build directory** (if I/O is the bottleneck)

```yaml
- name: Setup tmpfs for build
  run: |
    sudo mkdir -p /mnt/ramdisk
    sudo mount -t tmpfs -o size=10G tmpfs /mnt/ramdisk
    ln -s /mnt/ramdisk build
```

### Workaround (Immediate)

While investigating, use CMake caching:

```yaml
- name: Restore CMake cache
  uses: actions/cache@v3
  with:
    path: build/CMakeCache.txt
    key: cmake-cache-${{ runner.os }}-${{ hashFiles('base/CMakeLists.txt', 'base/vcpkg.json') }}
    
- name: Configure (skip if cached)
  run: |
    if [ -f build/CMakeCache.txt ]; then
      echo "Using cached CMake configuration"
      cmake -B build -S base
    else
      echo "Full CMake configuration"
      cmake -B build -S base
    fi
```
